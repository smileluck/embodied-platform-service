# 登录日志列表列宽随筛选跳动修复

## 问题

登录日志页（`web/src/views/log/LoginLogs.vue`）选择「成功/失败」筛选后，结果/说明/时间列位置明显移动：表格中「浏览器/终端」（user_agent）与「说明」（msg）两列未设宽度，naive-ui 按内容自适应布局——筛选成功时说明列全是「—」被压窄、浏览器列变宽；筛选失败时长错误文本撑宽说明列，且长文本换行使行高增加。

## 提案 / 决策

按仓库既有惯例（`system/Dicts.vue` remark 列等）给两个弹性列加 `minWidth` + `ellipsis: { tooltip: true }`：浏览器/终端 `minWidth: 180`（替代原 NEllipsis max-width 200px 的手写 render），说明 `minWidth: 140`。列位置不再随筛选内容变化，长文本省略号 + 悬浮提示。

## 真实考虑过的备选

| 备选 | 放弃理由 |
|---|---|
| 说明列固定 `width: 220` | 1280 视口下列宽总预算超容器，时间列被挤出卡片出现横向滚动 |
| 全部列固定宽度 | 需压缩既有列宽（用户名/IP 等），响应式余量变差；minWidth 惯例已够用 |

## 验收标准

- [x] 浏览器实测（vite dev + 本仓后端）：未筛选 / 筛选成功 / 筛选失败三种状态下结果、说明、时间列位置一致，无横向溢出
- [x] `npm run build`（含 vue-tsc）通过

## 风险与后果

- 长错误说明默认省略号截断，需悬浮查看全文（与全站其他列表页一致）
- 同类页面（操作日志/租户日志等）若出现相同投诉，按同一 minWidth+ellipsis 模式处理
