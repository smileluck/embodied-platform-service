# 租户权限码目录动态化（商户端注册表 → 平台按商户目录）

## 需求描述

租户门户的权限码（`device:*`/`member:*` 等）由商户端（本服务）开发——每个门户功能的权限码定义、路由挂载、前端文案都在本仓。但目录（配权 UI 可勾选的合法码清单）此前是平台仓静态代码，商户端每加一个权限码都要平台改码发版，双仓耦合。用户要求改为：商户端持有权限码注册表（事实源），服务启动时自动向平台同步注册，平台目录动态化（按商户隔离），此后新增门户权限码只需本仓发版。

## 状态

已完成（双仓代码 + 测试 + 文档；联调冒烟待 deploy 环境——前置：商户配 `tenant-role:syncPerms` scope、平台先行部署）

## 涉及范围

### 后端

- 本仓：`internal/biz/tenantuser/permcatalog.go`（权限码注册表，27 码含 dataset 域——平台 base 已撤下、由本表带回）、`internal/server/router.go` 挂载常量化、`internal/platformsdk` 补 `SyncTenantUserPerms`（PUT /open-api/v1/tenant-user-perms）、`cmd/server/main.go` 启动异步推送（30s 重试至成功；4xx 永久错误放弃并 error 提示）
- 平台仓：`tenant_perm_defs` 表（AutoMigrate，(merchant_id, code) 唯一）、开放面 PUT 注册端点（scope `tenant-role:syncPerms`，幂等只增不删）、目录 GET 按签名商户收敛（base ∪ 本商户注册码）、角色 NormalizePerms 校验同口径、`sdk/` 补方法

### 前端

- 无改动（目录数据源不变；本仓 i18n 已含全部 27 码文案）

## 约束与备注

- 部署前置：商户须配 `tenant-role:syncPerms` scope，否则启动推送被 403（日志明确提示）；平台先行部署
- 只增不删：商户端回滚版本不会收缩平台目录；废弃码治理留平台管理面后续
- 新增权限码三件套同发版：注册表一行 + 路由挂常量 + 前端 i18n 文案（tenantRole.perm/permGroup）
- 角色 perm_codes 存字符串关联表无外键，存量角色不受目录动态化影响
