# 系统管理模块接口权限改造计划

## 背景

- 权限体系：`permissions` 表统一存菜单（type=menu）与按钮权限点（type=button），button 绑定 `method/path` 参与 RBAC 中间件校验（默认拒绝 + 30s 内存缓存）。
- 现状：系统管理（用户/角色/菜单与权限）共 18 个受保护接口，但 button 权限点只有 2 个示例（`user:create`、`user:delete`），其余接口无对应权限记录。
- 种子数据仅在 users 表为空时写入，存量库需幂等迁移补数据。

## 一、Match 支持中间通配符（后端前置增强）

`internal/biz/permission/entity.go:35-56` — 现 `Match` 只支持尾部 `*` 前缀匹配，无法表达 `PUT /api/v1/users/*/roles` 这类子资源接口。改为 glob→regex 统一处理：`regexp.QuoteMeta` 转义后将 `\*` 替换为 `.*` 并锚定 `^...$`。尾部 `*` 语义不变（向后兼容），新增中间通配能力。

## 二、系统管理接口权限点清单（18 条 button 记录）

**用户管理（ParentID=111）** — 7 条：

| code | 名称 | method | path |
|---|---|---|---|
| user:list | 查询用户 | GET | /api/v1/users |
| user:view | 用户详情 | GET | /api/v1/users/* |
| user:create | 新增用户 | POST | /api/v1/users |（已有 id=120）
| user:update | 编辑用户 | PUT | /api/v1/users/* |
| user:delete | 删除用户 | DELETE | /api/v1/users/* |（已有 id=121）
| user:setRoles | 分配角色 | PUT | /api/v1/users/*/roles |
| user:resetPassword | 重置密码 | PUT | /api/v1/users/*/password |

**角色管理（ParentID=112）** — 6 条：`role:list/view/create/update/delete/setPermissions`（setPermissions → PUT /api/v1/roles/*/permissions）

**菜单与权限（ParentID=114）** — 5 条：`menu:list/view/create/update/delete`（对应 /api/v1/permissions 系列）

## 三、数据落库：幂等 ensure 迁移

`internal/data/data.go`：

1. 新增 `ensureSystemButtonPerms()`（18 条清单的单一来源）：逐条按 `code` 查找，缺失则插入（**不指定 ID**，避免与用户自建记录的自增 ID 冲突；只插不改，尊重可能的自定义）；同时确保 `role_permissions` 中 super_admin 角色（按 code 查询）绑定这些权限点（超管已有 `all` 通配实际全通过，绑定是为了角色权限树回显一致）。
2. 从 fresh seed 的 perms 列表移除 120/121 两条示例，改由 ensure 统一管理。
3. `migrateAndSeed` 结构：AutoMigrate → `migrateLegacy()` → （users 空则 seed 菜单/角色/admin）→ `ensureSystemButtonPerms()`（每次启动幂等执行，存量库与全新库统一走此路径）。

## 四、基础接口放开 RBAC（仅 JWT）

`internal/server/http.go:94-116` — `POST /auth/logout`、`GET /auth/profile`、`GET /menus` 移到仅挂 `middleware.JWT` 的分组（这三个是"自身数据"接口：menus 本身已按角色过滤，无越权风险）。否则非超管用户登录即 403 白屏。其余 users/roles/permissions 接口维持 JWT+RBAC 不变。

## 五、前端按钮显隐补齐（v-permission，与 Users.vue 现有模式一致）

- `web/src/views/system/Users.vue`：编辑 → `user:update`、重置密码 → `user:resetPassword`
- `web/src/views/system/Roles.vue`：新增 → `role:create`、编辑 → `role:update`、删除 → `role:delete`、分配权限 → `role:setPermissions`
- `web/src/views/system/Menus.vue`：新增（含新增子级）→ `menu:create`、编辑 → `menu:update`、删除 → `menu:delete`

角色权限树（Roles.vue）自动展示新 button 节点，无需额外改动。前端 rebuild + 强刷（air 托管 dist）。

## 六、验证

1. 重启服务（air 自动热重载跑迁移），确认日志与 DB 新记录（permissions 18 条 + role_permissions 绑定）。
2. curl：admin token 走一遍 18 个接口全 200。
3. 界面临时建"仅 user:list + 用户管理菜单"测试角色/用户，验证 GET /users 200、POST /users 403、GET /roles 403、profile/menus 200（注意 RBAC 有 30s 缓存），验证后清理测试数据。
4. `go build ./...` + 前端构建通过。
